# البنية الحالية

المشروع يجمع تطبيق الحكم للأندرويد وعميل Flutter Web للاعبين، وموقعاً تعريفياً ثابتاً مستقلاً. هذا وصف للتنفيذ الحالي؛ تفاصيل السعة المستقبلية في [خطة التوسع](architecture-100k.md).

| المسار | المسؤولية |
| --- | --- |
| `lib/presentation` | الشاشات، الثيمات، التنقل وعرض الحالة. |
| `lib/application` | تنسيق الجولات والإعدادات واستعادة الجلسة والصلاحيات. |
| `lib/data` | مستودعات الحساب والسجل والنتائج واتصال Firebase/API. |
| `packages/game_core` | قواعد اللعبة والمحركات وreducer بلغة Dart؛ المصدر المشترك للعميل والخادم. |
| `lib/domain` | أنواع وعقود التطبيق وإعادة تصدير المحرك المشترك للحفاظ على imports. |
| `services/game_api` | API موثوق تجريبي بـTypeScript لجلسات V2. |
| `services/game_engine` | خدمة Dart عديمة الحالة لتشغيل المحرك المشترك. |
| `website` | موقع ABWINI Labs الثابت وصفحة مافيا المستقلة على Sites؛ لا يكتب بيانات اللاعبين. |
| `web` | عميل اللاعبين الحالي على Firebase Hosting؛ روابط QR تبقى على نفس العنوان. |

## مسار التشغيل المنشور

- اللعبة الكلاسيكية تستخدم المحرك محلياً. لا يعتمد كل tick للمؤقت على كتابة Firestore.
- QR الحالي يستخدم Firebase Authentication وFirestore، مع بطاقات خاصة وعضوية يوافق عليها الحكم. يتصل كل لاعب ببياناته والمستندات المطلوبة للجلسة.
- النتائج تُحفظ مع إيصالات تمنع حسابها مجدداً. السجل يستعمل صفحات وملخصات؛ التقرير الكامل يُجلب عند فتحه.
- حذف السجل يحذف بيانات المباراة وأرشيفها مع إبقاء الإحصائيات وإيصالات مختزلة تمنع إعادة احتسابها.
- العودة من الخلفية تحفظ مسار التنقل. إنهاء المباراة يزيل مؤشر الاستعادة.

## Premium

`theme_catalog.dart` يعرّف أربع لوحات ثابتة: الأصلية المجانية وثلاث لوحات تحتاج صلاحية `themes`. الصلاحيات لا تُمنح بمجرد الضغط على زر ولا يستطيع العميل تعديل حقول entitlement المحمية. أسعار شاشة العرض لا تعني أن الفوترة مفعلة. المساعد الصوتي معلن فقط.

## المسار المستقبلي V2

يبقي المحرك واحداً في Dart وينقل التحقق والانتقالات إلى API موثوق، مع نسخ الحالة ومنع تكرار الأوامر وoutbox للنتائج. **الشيفرة والاختبارات موجودة، لكن V2 والخدمات المدفوعة غير مفعلة في النشر الحالي**. لا تُحذف هذه المجلدات على أنها مخلفات؛ إعداد نشرها والتحقق منها في [دليل التشغيل](server-v2-runbook.md).

100 ألف مستخدم هدف لتخطيط غرف موزعة، وليس قياساً مثبتاً. يتطلب مشروع اختبار وميزانية ومراجعة الحصص ثم اختبارات حمل تدريجية؛ لا يُشغّل على مشروع Spark الحالي.

## التحقق والبناء

الـCI يفحص Flutter وقواعد Firestore وAPI والموقع. محلياً استخدم `flutter test --concurrency=1`، وأداة `tool/verify_backend.py` تشغّل خدمات التحقق المؤقتة وتوقفها. APK يُبنى بأداة `tool/build_android_release.sh` مع عامل Gradle واحد وحدود للذاكرة. الموقع يُجمع بـ`python3 website/build.py` ثم `python3 website/build_worker.py` دون dependencies أو خادم أو متصفح.

## أدوات الحكم وإعادة المباراة (1.2.8)

تُحفظ آخر 40 حالة قرار في ذاكرة `GameOrchestrator` أثناء تشغيله، وتُستثنى تغييرات المؤقت. تُجمع تغييرات أمر الحكم الشبكي في خطوة واحدة. التراجع أثناء اللعب يعيد لقطة كاملة ويوقف مؤقت النهار، ثم يعيد إنشاء الشاشة للتخلص من الاختيارات المحلية. لا تتراجع هذه الأدوات عن نتيجة سبق حفظها، ولا تبقى قائمة التراجع بعد إعادة تشغيل التطبيق.

الطرد علم مستقل `isKicked` وحدث إداري، فلا يشغّل الانتقام ولا يحتسب إعداماً. تُلغى الحركات الليلية المعلقة التي تخص المطرود وتُراجع نتيجة الفوز. مقعده المرتبط يبقى معروفاً لعرض رسالة الطرد وإمكان التراجع، وتمنع القواعد أي إرسال منه.

في QR المنشور (V1)، التصحيح يعيد نشر الحالة والطلبات الخاصة في معاملة واحدة مع زيادة `stateVersion` و`actionRevision`. لا تعرض شاشة اللاعب طلباً بإصدار مختلف عن المرحلة العامة؛ تستعيد المستمعين عند الاستئناف وتعيد الاتصال بتأخير متزايد بعد خطأ نهائي، دون polling.

`sessionId` عنوان غرفة ثابت؛ `matchId`/`GameState.id` يتغير لكل إعادة. الإعادة لا تغيّر أسماء/معرّفات اللاعبين الباقين أو القواعد، وتتيح إعداد الأدوار فقط. العضوية و`linkedUid` يبقيان ثابتين، وتُمسح النتائج الخاصة والقدرات والأصوات عبر إصدار جديد. النتيجة تُحفظ قبل فتح الإعادة، ويمنع معرّف النتيجة الجديد دمج الإحصائيات. `closed` يفرّق الإغلاق اليدوي النهائي عن نتيجة مباراة تنتظر الإعادة. حذف سجل قديم لا يحذف غرفة استُخدمت لمباراة أحدث.

أدوات التصحيح والإعادة الجديدة تخص V1 الحالي. يجب إضافة أوامر موثوقة مكافئة إلى reducer/API قبل تفعيلها في V2؛ مسار V2 يبقى معطلاً في النسخة المنشورة.

الموقع محتوى ثابت يقدمه Worker صغير من R2 المدار بواسطة Sites، وAPK يُبث من مسار تنزيل مستقل عن GitHub. رفع الإصدار محمي بمفتاح مؤقت وبقائمة أحجام وSHA-256، ثم يُحذف المفتاح بعد الترقية إلى الملفات المرفوعة. لم تُفعّل خدمة Google مدفوعة أو ترقية Spark.
